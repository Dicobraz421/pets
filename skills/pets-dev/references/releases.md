# Выпуски Pets на GitHub

Решение владельца 2026-11-01: пользователь скачивает только со страницы Releases — понятные файлы, одна схема для
всех приложений, Linux добавляется без переделки. Артефакты Actions — для разработки. Образец — Postman
(`.github/workflows/ci.yml`, `docs/DEV.md` «Выпуск»).

## Тег и версия

- Тег `v<версия>` = `version` в `Cargo.toml` (CI сверяет, иначе красный). Без дефиса — стабильный выпуск, с дефисом
  (`v0.2.0-beta.1`) — предварительный (`--prerelease`).
- Выпустить: PR с новой версией (класс B) → merge → тег на `origin/main` → push тега. Остальное делает CI.

## Файлы выпуска — плоско

| Файл | Что |
|---|---|
| `<app>-<версия>-<os>-<arch>.zip` (Linux — `.tar.gz`) | Комплект целиком; `os` — `windows`/`linux`, `arch` — `x64`/`arm64` |
| Компоненты под своими именами (`postman-worker.exe`) | Один файл вместо комплекта, когда приложение сообщает о недостающем |
| `SHA256SUMS.txt` | Суммы всех файлов |

- Имена — нижний регистр, без пробелов. В архиве файлы лежат сразу, без вложенной папки; `README.txt` — установка,
  удаление, где скачать.
- Компонент — под тем именем, под которым лежит в папке программы: скачанный файл просто кладут, без переименования.
  Вторая архитектура той же ОС — компонентам суффикс `-<arch>`, приложение ищет оба имени.
- Описание выпуска — таблица «что скачать» (шаблон `.github/release-notes.md`, `{version}`) и список PR
  (`--generate-notes`).

## Ссылки из приложения

- «Проверить обновления» — `releases/latest` (стабильный канал) или `releases` (предварительный). Сети в фоне нет:
  только по щелчку, в браузере.
- Недостающий компонент — `releases/download/v<своя версия>/<файл>`: той же версии, что приложение.

## CI

- Job `release` — matrix по платформам (`platform: windows-x64`, `runner`). Скрипт упаковки платформы отдаёт `name`,
  `dir`, `assets`, `version`; на теге — проверка «тег = версия» и артефакт `release-<platform>`.
- Job `publish` — ubuntu, `contents: write`, `needs: [test, release]`, только на теге: скачивает `release-*`, считает
  `SHA256SUMS.txt`, `gh release create --verify-tag`.
- Linux — строка matrix и `scripts/linux/package.sh` с теми же выходами; `publish` не меняется.

## Установка: для всех или только для себя

Решение владельца 2026-11-04. Установщик (MSI, скрипт установки) даёт выбор области — везде, где формат это позволяет:

| Вариант | Куда | Права |
|---|---|---|
| **Для всех пользователей (администратор)** | `Program Files\<App>`, HKLM, ярлыки для всех | UAC |
| **Только для меня** | `%LOCALAPPDATA%\Programs\<App>`, HKCU, свои ярлыки | не нужны |

- **По умолчанию:** пользователь — администратор (в группе Administrators или процесс уже повышен) → «для всех»;
  иначе → «только для меня». «Для всех» без прав остаётся выбираемым (UAC спросит учётку администратора), если
  политика ОС не запрещает установку с повышением; запрещает — вариант недоступен, причина одной строкой рядом.
- **MSI** — двухрежимный пакет (WiX `Package Scope="perUserOrMachine"`, `ALLUSERS=2` + `MSIINSTALLPERUSER`),
  выбор — в окне установки, умолчание — по свойству `AdminUser`. Тихая установка: `ALLUSERS=1` (для всех) или
  `MSIINSTALLPERUSER=1` (для себя); без параметров — то же умолчание.
- **Скрипт установки** — параметр `-Scope Machine|User`, без него — умолчание по токену (`IsInRole(Administrator)`).
- **winget** — оба установщика в манифесте (`Scope: machine` и `Scope: user`); portable zip — без выбора
  (куда распаковали).
- **Обновление и удаление** — в той области, где уже установлено (по реестру), выбор не показывать. Установлено в
  обеих — обновлять обе.
- **Что требует прав** (регистрация источника журнала Windows, службы, общесистемные политики, помощник с
  повышенными правами) — только «для всех». В «только для меня» приложение стартует и работает без этого; недоступная
  функция — по правилу «Понятная проблема» (`pets-architecture`), не ошибкой старта.
- Права папки, которые в `Program Files` есть сами (например, чтение для ALL APPLICATION PACKAGES — песочнице
  AppContainer), в пользовательской папке установщик выдаёт сам.
- Проверка выпуска: установка, обновление и удаление в обоих вариантах — строкой в `docs/manual-tests/` выпуска.
