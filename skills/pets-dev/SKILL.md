# Разработка Pets: полосы + волны + автомерж

Решение владельца 2026-10-24. Основание — анализ 315 PR за 10 дней (`references/analysis-2026-10.md`).
Архитектура — скилл `pets-architecture`; этот скилл — только процесс.

## Модель

| Понятие | Правило |
|---|---|
| **Полоса** | Набор путей из `lanes.toml` (крейт или группа крейтов). Агент правит только свою полосу. Полосы не пересекаются. |
| **Волна** | 3–5 готовых задач одной полосы → одна ветка `w/<полоса>-<NN>` → один PR. Коммит на задачу: `<ID>: суть`. Целевой diff 200–800 строк. |
| **Класс A** | Код и тесты в полосе, docs, fix. Мержит merge queue на зелёном CI, без владельца. |
| **Класс B** | Пути из `CODEOWNERS`: контракты, `Cargo.toml`/`Cargo.lock`, ADR, `.github/`, песочница, `lanes.toml`. Нужен approve владельца. |
| **Бета** | Ежедневная сборка main (`workflow_dispatch`/тег `beta-*`). Ручная GUI-приёмка — пакетом по бете, мерж не блокирует. Найденное → новые карточки `fix`. |

Пересечь полосы можно только отдельным PR класса B (ветка `x/<суть>`): сначала контракт, потом волны.

## Параметры (рассчитаны, пересматривать по замерам)

- Агентов параллельно: 3 на стенде (Windows, gpui) + 1–2 облачных на крейты без gpui (L0–L2).
- Волна: 3–5 задач; задачи <30 мин работы обязательно собирать в волну.
- CI на PR и в merge queue: ≤7 мин. Docs-PR: 0 мин сборки (job `changes`). Release, размер, smoke, архив, подпись — только main и бета.
- Merge queue: метод rebase (коммиты задач сохраняются), группа ≤4, min 1, ожидание 2 мин, required check — `gate`.
- rust-cache: `shared-key: windows`, `save-if` только на main — PR и очередь берут тёплый кэш main.
- Локально: `sccache` общий для всех worktree, `CARGO_TARGET_DIR` свой у worktree (на Dev Drive).

## Цикл агента (одна волна)

1. Прочитать: `CLAUDE.md` (≤3 КБ), карточки волны `docs/tasks/<ID>.md`, **только** разделы из их поля `read:`.
   Большой документ — найти раздел (Grep по заголовку), читать `Read` с offset/limit. Поиск по коду — субагент Explore.
2. Ветка от свежего `main`: `git switch -c w/<полоса>-<NN> origin/main`.
3. На каждую задачу: код → `cargo check -p <крейт>` (инкрементально) → коммит `<ID>: суть`.
4. В конце волны, один раз:
   `cargo fmt --all` · `cargo clippy -p <затронутые> --all-targets -- -D warnings` ·
   `cargo nextest run -E 'rdeps(<затронутые>)'` · снимки только затронутых сцен **dev-сборкой**.
   Release — только если в карточке есть перф/размер.
5. Ручная проверка — файл `docs/manual-tests/<ID>.md` (шаги + ожидание), не общий список.
6. `git push -u origin HEAD` → `gh pr create` (тело: список ID, что не сделано) → `gh pr merge --auto --rebase`.
7. Не ждать мержа: следующая волна полосы — от ветки текущей; после мержа `git rebase origin/main` (полоса своя — конфликтов нет).
8. Красный CI: одна правка с причиной. Нестабильный тест — чинить причину, не перезапускать.
9. Отчёт оркестратору ≤5 строк: PR, что не сделано, вопросы «Решения для владельца».

Агент **не** трогает: чужие полосы, `Cargo.toml`/`Cargo.lock` (зависимость нужна → карточка в полосу `deps`),
генерируемые файлы (`COMMANDS.md`, `PARITY.md` — их обновляет полоса `docs-gen`), `.github/`.

## Ноль общих файлов

Файл, который трогает каждый PR, = конфликт + пересборка + чтение целиком. Поэтому:
- Ручные проверки — `docs/manual-tests/<ID>.md`; старый общий реестр заморожен как архив.
- Решения — `docs/decisions/<YYYY-MM-DD>-<slug>.md`, без сквозных номеров; индекс генерируется.
- Контракты — один текущий `docs/CONTRACTS.md` + `CHANGELOG` в нём; старые версии в `docs/archive/`.
- Строки `.ftl` — файл на часть экрана.
- Реестры экранов, команд, сцен — регистрация в модуле фичи, не правкой центрального `main.rs`/`mod.rs`.
- `CLAUDE.md` — только стабильные правила, ≤3 КБ, без «текущей сессии». Текущее — в карточках.
- Документы — только в репо. Чаты читают их через git; в Project — ARCH-BASELINE и индекс.

## Оркестратор (чат S0 / «Джарвис»)

1. Спека сессии → карточки `docs/tasks/<ID>.md` по шаблону (`templates/task-card.md`), одним PR класса A.
2. План волн: по каждой полосе следующие 3–5 карточек с закрытыми `deps`. Карточка с `files` вне своей полосы —
   разбить или вынести контракт в PR класса B.
3. Запуск: по агенту Claude Code на полосу (worktree `../<repo>-<полоса>`), промпт — `templates/agent-prompt.md`.
   Облачный агент (полосы без gpui) — `python cloud_agent.py run <repo> <полоса> <NN> <ID>...`, затем `wait`;
   он пушит ветку `w/<полоса>-<NN>`, PR открывает оркестратор (`gh pr create` → `--auto --rebase`).
4. Владельцу — только PR класса B и итог беты. Вопросы — пакетом «Решения для владельца».

## Экономия токенов

- Старт агента ≤5 КБ контекста: `CLAUDE.md` + карточки. Остальное — по ссылке `read:` и точечно.
- Не перечитывать файл после правки; не выводить полные логи — `| tail -40`, ошибки компиляции пачкой.
- Отчёты и тела PR — короткие списки. Повторяющееся знание → рецепт в `pets/docs/recipes/`, не в CLAUDE.md.

## Шаблоны и внедрение

`templates/`: `ci.yml`, `lanes.toml`, `CODEOWNERS`, `lane_check.py`, `task-card.md`, `agent-prompt.md`, `CLAUDE.md`.
Перевод репозитория на схему — `rollout/<repo>.md` (задачи R-NN для Claude Code).
Разовые настройки GitHub (владелец) — `rollout/github-settings.md`.
