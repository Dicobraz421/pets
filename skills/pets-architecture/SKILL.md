# Архитектурный базис «Pets»

Источники: репозиторий **pets** (`github.com/Dicobraz/pets`) — `docs/decisions.md` (решения по общему коду, приоритетнее), общие крейты и `docs/recipes/` (проверенные подходы с пометкой применимости); Postman (`docs/specs/S0-decisions.md`, `docs/PATCHES.md`) — эталон стека gpui; Урфин (`filenav/00-ARCHITECTURE.md`, `S0-decisions.md`) — эталон процесса и архитектуры ядра (интерфейс Урфина на gpui с 2026-10-20, ADR-0018). При конфликте — читать их, а не этот файл.

**Правило:** всё ниже — умолчание для любого нового приложения. Отступление — только явным ADR с решением владельца; в концепте отступления помечать «⚠ отступление от базиса: причина».

## Порядок работы
1. Концепт сначала в чате (экраны, модули, решения на выбор). Файлы/спеки — только после согласования.
2. Экономия токенов: читать только нужные доки, пояснения — по сути.
3. Вопросы владельцу — пакетом «Решения для владельца» (№, вопрос, рекомендация), не по одному.
4. Офлайн: никаких CDN/скачиваний в рантайме, ресурсы — системные или вшитые.

## Стек и платформа
- Rust stable, edition 2024; интерфейс — **gpui** (gpui-kit: gpui-pre + gpui-component, версия фиксирована) для всех приложений. egui отвергнут (решение 2026-10-19); Урфин перешёл на gpui (ADR-0018).
- Рендер на Windows — собственный gpui (Direct3D 11, DirectWrite) с нашими патчами платформы (`pets-gpui-windows`): кадры по запросу (0 % CPU в простое), живой ресайз (кадр на `WM_SIZE`, swapchain окна с растяжением, DirectComposition выключена — Mica за содержимым недоступна).
- Платформа: **Windows 11 — основа**; другие ОС (Linux, macOS) — по запросу владельца. Решения, не завязанные на ОС, принимаются с учётом остальных платформ: код вне `sys` кроссплатформенный, чтобы ОС можно было вернуть без переписывания.
- Лицензия — проприетарная, все права защищены (решение 2026-11-11 «license»). Издатель **Aahz** (winget `Aahz.<App>`). Технические имена — ASCII lower-case (`<app>-*` крейты, `%APPDATA%\<App>`, `<APP>_LOG`).
- Зависимости — минимум; каждая новая: лицензия (cargo-deny), вес в бинаре, дубли в графе.

## Архитектура
- Workspace `crates/*` слоями: L0–L1 доменные крейты без UI → L2 `core` (без UI) → L3 интерфейс на gpui (бинарь). Слои проверяет тест по `cargo tree` (ниже L3 нет gpui/winit/диалогов). `unsafe` — только в `sys/{windows,…}.rs`.
- Общий код — git-зависимостью из `pets` с фиксированной ревизией: `pets-commands`, `pets-i18n`, `pets-shell`, `pets-ui`, `pets-gpui-windows`. Крейт в `pets` — только с потребителем; предметное — в приложении.
- Любое действие пользователя → команда из реестра (`pets-commands`: id `область.действие`, хоткеи, контекст) → действие gpui → handler. UI только рисует состояние.
- Экран — набор view со своим состоянием, встроенных через `.cached(...)` с явным размером; связь частей — событиями (рецепт «кэшируемые view»).
- **UI-поток не делает I/O.** io-pool (blocking, N настраиваемо), cpu-pool (rayon), отдельные потоки-читатели для потоков данных.
- Отмена — токен в каждой задаче; прогресс — атомики, события ≤30/с.
- Repaint только по событию; в простое 0% CPU.
- Виртуализация списков/текста — рендерится только видимое; данные окна списка читаются в фоне с упреждением (рецепт «окно строк»).
- Single-instance (mutex + named pipe, JSON `{argv,cwd}`), `--new-instance` для отладки. Восстановление сессии. Настройки — профиль ОС; portable по файлу-флагу.
- Ошибки: thiserror (либы) / anyhow (app). Логи: tracing; Error-события и падения дублировать в журнал Windows «Приложение» (источник регистрирует MSI).
- Секреты (токены, пароли, ключи) — только в памяти до выхода, на диск не пишутся без явного хранилища ОС.

## UX и визуальный язык
- **Единый стиль всех приложений Pets** (решение 2026-10-20): общие токены, темы и компоненты — в `pets-ui`; приложение не вводит собственную палитру.
- **Ноль модальных окон**: диалоги — inline-оверлеи; подтверждения — одной строкой inline.
- Уведомления — тосты справа сверху: info 4 с / warn 6 с / error 8 с, с действием 15 с; стек ≤3 (+N); фокус не забирают; детали — в лог; история уведомлений командой.
- **Понятная проблема — описание, причина, решение** (решение 2026-11-01): что случилось, почему и как исправить — словами пользователя, со способом исправить в один шаг (кнопка, ссылка на загрузку, путь, куда положить), а не «переустановите всё». Интерактивно: в строке состояния — короткий статус без технических имён, пока проблема есть; по щелчку — описание, причина и действие; проблема ушла (файл положили, связь вернулась) — статус снимается без перезапуска. Сервер — то же в журнале, API (код, причина, способ исправить) и админ-консоли. Пока проблема есть — ни повторов впустую, ни CPU в простое.
- Windows Fluent, ориентир WinUI Gallery: акцент и светлая/тёмная — из ОС; **Mica не используем** — сплошной фон каркаса (решение 2026-10-20); табы в заголовке окна; цифры tabular; размеры — ≤1 знак после запятой.
- Шрифты на Windows — системные, не вшиваем: Segoe UI Variable → Segoe UI; моно Cascadia Mono → Consolas; иконки Segoe Fluent Icons → MDL2 Assets.
- Клавиатура — первична: реестр команд → сочетания, пресеты, пользовательский keymap; системные хоткеи ОС не перехватываем; клавиши без модификаторов — вне полей ввода (`!Input`); работа в любой раскладке проверяется скриптом.
- i18n: EN+RU на Project Fluent, lint на сырые строки; язык BCP-47; даты на Windows — через API ОС.
- Текст/код: подход редактора Урфина (rope, `syntect` в фоне, инкрементально, вшитый pack ≤2 МБ, >16 МБ без подсветки) — реализация на gpui, общая — в `pets`, когда появится потребитель.

## Темы оформления (решение 2026-10-20)
- Цвета — только через **токены ролей** (frame, panel, text, secondary, accent, cursor, cursor-text, marked, border, error, warning, success + роли типов файлов в приложениях-потребителях). Литералы цвета в коде UI запрещены (lint). Реализация — `pets_ui::theme`: имена ролей — токены Урфина (`text.primary`, `layer.panel`, `fill.cursor`…), роли приложений — `app.*`; соответствие — рецепт «Темы оформления» в pets.
- Тема = TOML с ролями; пользовательские темы из профиля, горячая перезагрузка из файла без рестарта.
- По умолчанию — режим **«как в ОС»**: светлая/тёмная/высокая контрастность и акцент из Windows, переключение на лету.
- Встроенные темы: **Fluent светлая**, **Fluent тёмная**, **Высокая контрастность** (из ОС) — обязательные; **Графит** (почти без цвета, курсор яркостью) и **Navigator** (ретро DN/Far) — встроенные дополнительные; **Бумага** (тёплая, мягкий контраст) — опционально.
- Navigator — утверждённое отступление: моно-шрифт во всём UI и собственные цвета вместо акцента ОС.
- Плотность строк: 20 / 24 / 28 / 32 px (32 — «стандарт» Урфина), по умолчанию **24 px**.
- Иконки: нет / Segoe Fluent моно / цветные по типу; по умолчанию **Segoe Fluent моно**.
- Корпоративное: тему и запрет её смены задаёт политика (реестр HKLM\Policies / ADMX); **индикатор контекста** — цветная полоса заголовка при запуске от администратора или в удалённой сессии, политикой не отключается.

## Бюджеты (считаются для каждого проекта на этапе ТЗ — не догма)
Цифры ниже — бюджеты Урфина, ориентир для нового ТЗ. Проект задаёт свои в ТЗ (память, старт, кадр, простой, бинарь) с учётом домена; дальше это гейты проекта. Мерить на Windows, в release.
- Первый кадр тёплый <250 мс; своё время старта без окна/устройства <20 мс.
- Кадр ≤2 мс на 100k строк; ввод ≤1 кадр.
- Своя память <50 МБ (feature `count-alloc`); процесс private ≤200 МБ.
- Бинарь <15 МБ (пересматривается явно, с обоснованием).

## Процесс
- Работа разбита на сессии-чаты `S0…Sn`; S0 — оркестратор (архитектура, контракты, решения, выдача задач Claude Code).
- Спеки сессий: цели, задачи `Sx-NN` (зависимости, приёмка), «Решения для владельца». Документы: `docs/specs/Sx.md`, `docs/adr/NNNN-*.md`; копии ключевых — в Project.
- Стенд — Windows 11 владельца нативно, там работает Claude Code; репо на Dev Drive (ReFS) + исключения Defender.
- Проверка: L0 стенд (MSVC, clippy pedantic=warn, cargo-nextest) → L1 CI windows (другие ОС — когда подключены по запросу) → L2 ручная приёмка владельцем (`win-manual`). Бенчи — criterion + hyperfine + бенч приложения (рецепт «бенч»: чередование бинарей, частота экрана и питание).
- Спека фазы сверяет возможности сервера и платформы с клиентом: таблица «используется / в плане / не нужно (почему)»
  (у Postman пропустили автоответ, общие ящики, Sieve, квоту — нашёл владелец).
- Параллельная работа — агенты в отдельных worktree по разным модулям; общий шов (интерфейс к серверу, файлы
  текстов на часть экрана) закладывается до запуска, чтобы агенты не правили одно место; сводит PR оркестратор.
- Агенты не управляют окнами синтетическим вводом — только снимки экранов, тесты и ручная приёмка владельцем.
- Процесс разработки (полосы, волны, автомерж, CI, экономия сборок и токенов) — скилл `pets-dev`.
- Ветки и PR — по `pets-dev` (волна полосы = PR). Релиз: MSI + portable zip + winget.

## Чек-лист нового приложения
1. Назначение и 3–5 ключевых сценариев.
2. Карта крейтов по слоям и набор команд (реестр `pets-commands`).
3. Где тяжёлые данные → виртуализация, фоновая обработка, стриминг.
4. Экраны в Fluent без модалок, в токенах тем `pets-ui`; клавиатурная карта.
5. Секреты и офлайн-ограничения.
6. Бюджеты — посчитать для проекта в ТЗ (Урфин — ориентир).
7. Что берём из `pets` (крейты и рецепты) и чего там не хватает — кандидаты в общий код.
8. Разбивка на сессии и вехи M1…; «Решения для владельца».
## Находки
Грабли gpui, стенда и сборки — `docs/recipes/gpui-pitfalls.md` в pets: читать перед работой с gpui, дополнять сразу по находке (PR в pets).
- `img` без заданной высоты (`w_full()`, `max_w_full()` у картинки шире колонки) берёт **родную высоту кадра**, и
  `Contain`/`ScaleDown` центрирует картинку в ней — «большой кадр не рисуется / рисуется со сдвигом» (Postman S5-07).
  Рендер DX11 большие и обрезанные кадры рисует верно; высоту задавать обёрткой с `aspect_ratio` внутри flex-строки (`flex_1().min_w_0().max_w(w)`), у `img` — `size_full`
  (рецепт gpui-pitfalls, «Картинки»).
- Прежде чем чинить «баг gpui», воспроизвести его минимальным примером со снимком и сверкой пикселей.
