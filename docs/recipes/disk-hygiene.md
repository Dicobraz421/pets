# Гигиена диска

**Применимость:** любое приложение, стенд Windows.

**Проблема.** Сборки и тестовые данные съедают диск: полная отладочная информация зависимостей (PDB в гигабайты),
`incremental`, каталоги профилирования, датасеты бенчей и брошенные временные каталоги.

**Решение.**
- Профиль dev: `debug = "line-tables-only"` (стектрейсы с файлом и строкой), у зависимостей `debug = false`.
- Общий `CARGO_TARGET_DIR` на Dev Drive (`scripts/stand/setup-windows.ps1`) — зависимости (gpui и др.)
  собираются один раз на все репозитории. Нет Dev Drive — не трогать.
- Код и скрипты не зашивают `target/`: каталог — из `cargo metadata` (`target_directory`).
- Чужие таргеты (macOS, Linux) не собирать на стенде — это CI; проверка `cfg` — `cargo check --target`.
- Агенты: тесты с БД и внешними сервисами — CI, без локальных Docker-контейнеров и томов; worktree и временный `target`
  удаляются в конце волны (скилл pets-dev, «Ресурсы агента»).
- Тесты: только `tempfile` (удаляется при drop), префикс `<app>-`; никаких ручных каталогов в `%TEMP%`.
- Датасеты бенчей — `%LOCALAPPDATA%\Pets\testdata\<app>\<dataset>`, переиспользуются при том же сиде; рабочая
  копия после прогона удаляется (флаг `--keep` — оставить).
- Периодически — `scripts/stand/clean.ps1` (показывает объём, удаляет по `-Apply`).

**Откуда.** Решение владельца H-01 (2026-10-19), `docs/TASKS-HYGIENE.md` в репозиториях.
