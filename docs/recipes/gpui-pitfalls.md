# Грабли gpui и стенда

**Применимость:** любое приложение на gpui (gpui-kit 0.7.3 = снимок `gpui-pre` 0.3.9), Windows.

Короткие находки: что неожиданно и как обойти. Дополнять по ходу работы.

## Ввод
- `gpui_kit::open_window` оборачивает view в свой `Root`: он вешает Tab/Shift+Tab на переход фокуса и Ctrl+C
  на Copy (контекст `Root`). Привязки срабатывают **раньше** `on_key_down`/`capture_key_down` — Tab туда не
  доходит. Свой конвейер клавиш — через `cx.intercept_keystrokes` (до привязок; `cx.stop_propagation()`, если
  клавиша забрана), или свои `key_context` + `cx.bind_keys` (глубже `Root` — главнее).
- Windows-платформа gpui сначала шлёт окну своё `WM_GPUI_KEYDOWN` (`WM_USER+8`, приватная константа) с теми же
  параметрами и только если gpui клавишу не обработал — настоящий `WM_KEYDOWN`. Хук окна (subclass), которому
  нужны все нажатия, ловит `WM_GPUI_KEYDOWN` и пропускает следующий за ним такой же `WM_KEYDOWN`. При
  обновлении gpui константу перепроверить.
- Shift+цифра и Shift+знак приходят готовым символом без Shift (`Shift+1` → `"!"`), серый «+» и `Shift+=` —
  оба `"+"`: различать по коду клавиши из хука. Ctrl+серая `*` не даёт ни клавиши, ни символа.

## Окно
- `observe_window_bounds` срабатывает на ресайз, но не на перемещение окна: геометрию для сессии снимать ещё и
  в `on_window_should_close`. Координаты `window_bounds()` — свои логические, но круговой путь (сохранить →
  открыть с этими `WindowBounds`) точный.
- Скриншоты `computer-use` снимают один монитор: окно на втором не видно — `switch_display` или
  `GetWindowRect` + `CopyFromScreen`/`PrintWindow`.

## Простой и кадры
- Без `pets-gpui-windows` gpui в простое ~2 % ядра (поток vsync); с патчем — 0,05 %.
- Будить UI из воркеров: каналов gpui не экспортирует — `futures::channel::mpsc::unbounded` + задача
  `cx.spawn` на основном потоке, пачку сигналов сливать в один проход, `wake_after` — `background_executor().timer`.
- Таймер на каждом кадре (`spawn` + `timer` + `notify` в `render`) — цепочка самопробуждений: держать один
  отложенный таймер (флаг «уже стоит»).

## Рендер
- gpui DX11 перебирает адаптеры `EnumAdapters` и берёт первый, где создаётся устройство; WARP («Microsoft
  Basic Render Driver») — последний, так что при сбое оборудования откат на WARP автоматический.
  Принудительно — `GPUI_FORCE_WARP=1` (патч `pets-gpui-windows`); в Rust 2024 `std::env::set_var` — `unsafe`,
  ставить до запуска потоков.
- Стиль наведения (`.hover`, у `.active` так же) задаётся элементу один раз: второй вызов поверх заготовки
  кнопки (`quiet(…).hover(|d| d)`, чтобы «снять» подложку) в отладочной сборке — паника «hover style already set»
  (`div.rs`, `debug_assert`), в release молча берётся последний. Заготовку делить на «без наведения» и «с ним»;
  ловится полным `--screens` в dev-сборке (Postman S5-16b).

## Картинки
- `img` без высоты (`img(x).w_full()`, или `.w(px(w)).h(px(h)).max_w_full()`, когда колонка уже кадра) — **не**
  «высота по пропорции»: `Img::request_layout` gpui-pre 0.3.9 подставляет в `Auto`-высоту **родную высоту кадра**
  в px (по пропорции — только если ширина задана абсолютно), а `ObjectFit::Contain`/`ScaleDown` ставит уменьшенную
  картинку **по центру** этой высоты. Кадр 1060×1500 в колонке 440 px: элемент 440×1500, картинка 440×623 на
  438 px ниже верха — сверху пусто (или видна тень родителя), низ уходит за край прокрутки. Выглядит как «кадр
  больше 1024 px не рисуется» и «обрезанный прокруткой кадр рисуется со сдвигом» (Postman S5-07), но рендер ни
  при чём. Обход — высоту задаёт обёртка по пропорции кадра, у `img` обе стороны заданы:
  `div().w_full().max_w(px(w)).aspect_ratio(w / h).child(img(x).size_full())`.
- В растянутой flex-колонке (абзацы письма) и этот обход оставляет пустоту под картинкой уже колонки: taffy
  считает высоту по `aspect_ratio` от ширины **до** ограничения `max_w` (логотип 300×200 — ~120 px пусто снизу).
  Рамку ставить в flex-строку: `div().w_full().flex().child(div().flex_1().min_w_0().max_w(px(w)).aspect_ratio(w / h)
  .child(img(x).size_full()))` (Postman S5-07б, `app-gpui/src/preview.rs`, `picture()`).
- Родитель `img` — flex: в блочном `div` (по умолчанию `Display::Block`) `img` с заданными `w` и `h` получил
  высоту по пропорции кадра (600×420 вместо 600×300).
- Сам рендер DX11 (`pets-gpui-windows`) кадры больше 1024 px и обрезанные маской рисует верно: атлас заводит
  под большой кадр свою страницу (до 16384), обрезка — `SV_ClipDistance` без пересчёта UV. Проверка —
  тест `image_sprite` в крейте и пример `cargo run -p pets-ui --example image_check -- <каталог>` (снимок
  `PrintWindow` + сверка пикселей «координатного» градиента; панели D/E — ловушка и обход). Upstream (Zed) —
  тот же `Img::request_layout` и атлас; в gpui чинить нечего, кандидат разве что в документацию `img`.

## Память
- gpui DX11 держит на каждое окно промежуточные текстуры путей (`paint_path`: обычная + MSAA 4×, размером с
  окно — 5 поверхностей): ~33 МБ на 1600×1000, ~17 МБ на 1025×850. На встроенной графике (Intel) это память
  процесса, а освобождённые при ресайзе текстуры драйвер отдаёт не сразу — пик +55…+115 МБ. Пути рисуют только
  `canvas` с `PathBuilder` (пунктирный `Separator`, стрелка `Popover`, графики, рамки выделения в редакторе);
  скругления, рамки и тени — квады, не пути. С `pets-gpui-windows` (ленивые текстуры путей) они создаются в
  первом кадре с путями и сбрасываются при ресайзе: Postman, демо 50 тыс., простой 130–137 → 98–106 МБ,
  пик 171–227 → 105–115 МБ.
- При ресайзе снимать текстуру путей со слота 0 шейдеров (`PSSetShaderResources(0, [None])`): контекст D3D
  держит ссылку на последнюю привязанную SRV, и без этого старая текстура живёт до следующей отрисовки с текстурой.
- Есть ли в окне пути — строка `path textures WxH` в журнале на уровне debug
  (`POSTMAN_LOG=gpui_windows::directx_renderer=debug`). В снимках `--screens` Postman путей нет ни в одной сцене.
- Память D3D на встроенной графике — счётчик `\GPU Process Memory(pid_<PID>*)\Shared Usage`; рабочий набор
  сравнивать только на одной машине (на дискретной GPU текстур в нём нет).

## Старт
- Замер «первый кадр» через `cx.on_next_frame` при кадрах по запросу ждёт **любого** следующего кадра —
  на первом `render` просить `window.request_animation_frame()`, иначе цифра — время до первого изменения.
- `pets-gpui-windows` до f762a5f: новое окно рождалось с запрошенным кадром, но поток vsync не будился —
  первую секунду (`IDLE_VSYNC_CHECK`) окно не обновлялось, первый кадр Урфина «1,1 с». Флаг-запрос, который
  будит поток только на переходе «нет → да», надо будить и там, где флаг взводится при создании.
- Шейдеры — байткодом из `build.rs` (`D3DCompile` хоста, без fxc.exe): 18 компиляций при запуске — ~256 мс.
- Профиль старта сэмплером — только верхушки стека: пока поток грузит DLL, раскрутка
  (`RtlLookupFunctionEntry`) из другого потока ждёт блокировку загрузчика — взаимная блокировка.

## Цена кадра
- Сборка дерева в `render` дёшева (у Урфина ~0,25 мс), дорого то, что gpui делает потом: профиль панели на
  ~70 видимых строк — половина кадра в раскладке taffy (`compute_layout`, flexbox), ещё ~11 % `request_layout`,
  ~9 % paint. Каждая строка из 4–5 flex-`div` с текстом (текст меряется taffy, иногда не раз) — дорого.
  Длинные однородные списки рисовать **одним своим `Element`**: фон — `paint_quad`, текст —
  `text_system().shape_line` + `paint` (кэш строк gpui), клики — по координате на контейнере.
- gpui по умолчанию ограничивает **неактивное** окно 30 кадр/с (`WindowOptions::inactive_frame_interval` =
  33 мс): владелец переключился в другое окно — замер «вдруг» 34 мс на кадр. Бенч: `inactive_frame_interval:
  None`, `focus: false`, `display_id` — неосновной экран, чтобы не мешать владельцу.
- Кэш поддерева: дочерняя view `entity.cached(StyleRefinement::default().size_full())` — кадр без `notify`
  этой view повторяется без раскладки и paint. `notify` дочерней view изнутри `render` родителя действует
  только со следующего кадра (`draw_phase` ≠ None): изменилась — в этом кадре вставить её без `cached`.
- Кэш **не повторяет** `WindowControlArea` (`window_control_hitboxes` нет в `reuse_paint`/`reuse_prepaint`
  gpui-pre 0.3.9): закэшированный заголовок теряет перетаскивание, «─ □ ✕» и Snap. Кэшировать только
  содержимое заголовка, кнопки и зону `Drag` — вне кэшируемой view.
- `GetThreadTimes` квантован тиком планировщика (~15,6 мс): CPU на кадр так не измерить, только за фазу.
- Профиль без WPT: сэмплер в процессе — `SuspendThread` + `GetThreadContext` + `RtlVirtualUnwind`, имена —
  dbghelp `SymFromAddrW` (путь поиска — папка exe, иначе PDB своего exe не найдётся). `CONTEXT` выровнять по
  16 байт (`#[repr(align(16))]`), иначе `ERROR_NOACCESS` (998). Пока поток стоит — не выделять память (куча
  может быть заперта им). Профиль release с `debug = "line-tables-only"`, `strip = false` даёт имена функций.

## Сборка и зависимости
- Не делать `cargo update -p <патченный крейт>`: MSRV-резолвер переразрешает чужие зависимости (у Урфина
  `gpu-allocator` уехал на `windows 0.58` — сломался `wgpu-hal`). Вернуть `Cargo.lock` и дать cargo применить
  патч самому (`cargo metadata`).
- cargo-deny с gpui-kit: лицензии 0BSD (`enum-iterator*`) и CC0-1.0 (`hexf-parse`, `notify`, `tiny-keccak`) —
  исключениями по крейтам; «unmaintained» (instant, paste, rustybuzz, ttf-parser, zbus/zvariant,
  rustls-pemfile) — в `ignore` с причиной; `reqwest` у gpui-kit-assets — только wasm.
- Вес: приложение только на gpui — 20–24 МБ; egui и gpui в одном exe — ~30 МБ.
- Несколько тяжёлых сборок параллельно (агенты, release с LTO) роняют rustc: `STATUS_STACK_BUFFER_OVERRUN`
  (0xc0000409). Лечится повтором с `-j 4`; замеры — только на тихой машине.

- Размер exe (Postman S5-13, `docs/SIZE.md` Postman): на MSVC таблицы раскрутки и код очистки паник — около 30 %
  exe на gpui (`panic = "abort"`: 36,9 → 25,8 МиБ у Postman); паники в `wndproc` gpui и так обрывают процесс
  (`extern "system"`), меняется поведение только своих потоков. Кросс-сборка mingw даёт exe меньше MSVC на ~4 МиБ —
  сравнивать размеры одной цепочкой сборки.
- Объединение features в рабочей области: gpui включает 14 форматов `image`, и любой бинарь с `ImageReader`
  тянет их все (у Postman — воркер-песочница +1,2 МиБ). Вне gpui звать декодеры форматов напрямую
  (`PngDecoder`, `JpegDecoder`…), а не `ImageReader`.

## Проверка картинки
- «Мерцает / пустой кадр» проверять не глазами: зонд на DXGI Desktop Duplication (Урфин,
  `scripts/stand/frame-probe`) берёт каждый кадр DWM в прямоугольнике окна и считает полосу курсора и
  «чернила». Прямоугольник окна брать после паузы (окно ещё разворачивается); кадры с чужой палитрой —
  окно перекрыто, их не смотреть и удалять.
- Снимок окна — `PrintWindow(PW_RENDERFULLCONTENT)`, не `CopyFromScreen` по его прямоугольнику: второй
  захватывает окна поверх (личные данные владельца).
- Таймеры `background_executor().timer` на Windows кратны ~15,6 мс: 33 мс превращаются в ~47.
- При переносе списка на свой `canvas` перенести все украшения строки, а не только фон: у Урфина пропала
  рамка 1 px активного курсора — бледная заливка без неё при движении читается как мерцание.

## Стенд владельца
- Два монитора.
- В Windows выключены «Эффекты прозрачности» (Mica не видна ни у одного окна) и «Макеты прикрепления при
  наведении на кнопку развёртывания» — перед погоней за «багом» проверить реестр (`Themes\Personalize`,
  `Explorer\Advanced`).

**Откуда.** Урфин, переезд на gpui (ADR-0018, G-01…G-07); Postman (S2), 2026-10-19…20.
- В Rust 1.99 `gpui::Window::window_handle()` (свой метод) затеняет `raw_window_handle::HasWindowHandle` —
  звать явно `HasWindowHandle::window_handle(window)`.
- `PrintWindow` своего окна — не с UI-потока (там он реентерабельно зовёт wndproc gpui посреди render):
  `cx.background_spawn` с HWND как `isize`, ждать в `cx.spawn`. С выключенной DirectComposition
  `PW_RENDERFULLCONTENT` снимает содержимое (Postman S2-05, `--screens`).
- `border` — один цвет на все стороны: цветной маркер слева — отдельным абсолютным дочерним `div`
  (тосты `pets-ui`).
- Fluent: `bundle.set_use_isolating(false)`, иначе U+2068/U+2069 рисуются «тофу» (`pets-i18n`).

- Журнал событий с незарегистрированным источником (без админа): `Get-WinEvent -FilterHashtable
  @{ProviderName=…}` падает «нет провайдера» — `-FilterXPath "*[System[Provider[@Name='X']]]"`, текст —
  в `.Properties`, не `.Message` (рецепт pets-shell).
**Postman S3–S4 (2026-10-20):**
- Обновить entity изнутри её же `update` (окно встречи трогает `Mailer`, пока `Mailer` обновляется) — паника
  «already borrowed»: второе обновление — через `cx.defer`.
- Свои диалоги файлов не нужны: `cx.prompt_for_paths` / `cx.prompt_for_new_path` — нативные окна Windows,
  поток интерфейса не ждёт (rfd не тянуть).
- Клавиши по разделам экрана: `key_context("Mailer MailView")` — несколько идентификаторов через пробел;
  привязки `MailView && !Input` молчат, когда открыт другой раздел (иначе Delete в календаре удалял письмо из
  скрытого списка).
- Свой манифест exe конфликтует с манифестом gpui (тот же номер ресурса): линковка падает, если язык совпадает.
  Свой — language-neutral, Windows берёт его; тест на `GetACP() == 65001` (activeCodePage UTF-8) ловит, что
  манифест применился.
- `windows_subsystem = "windows"` в release: для `--bench`, `--screens`, `--help` — `AttachConsole(ATTACH_PARENT_PROCESS)`,
  если stdout не перенаправлен; cmd не ждёт оконную программу — `start /wait`, в PowerShell — `| Out-Default`.
- Песочница AppContainer вне Program Files не стартует без права `*S-1-15-2-1:(OI)(CI)(RX)` на каталог exe —
  выдаёт сценарий установки (`icacls`), не приложение.
- `#[expect(dead_code, reason = "…")]` с кириллицей ловит тест сырых строк (`pets_i18n::raw_strings`) —
  причины в атрибутах писать по-английски.
- reqwest берёт `HTTPS_PROXY` из окружения: внутренние адреса — в `NO_PROXY` (`10.0.0.0/8` поддерживается).

**Параллельные агенты (процесс):**
- Агенты в отдельных worktree с общим `CARGO_TARGET_DIR`: сборки ждут блокировку — это нормально; ложное
  «cannot find X» в path-крейте после сборки другого worktree — `touch <крейт>/src/lib.rs`.
- Агенты не управляют окнами синтетическим вводом (SendInput, вставка из буфера, computer-use): на стенде
  владельца нажатия уходят в окно на переднем плане (так текст попал в окно Claude). Только снимки `--screens`,
  тесты и чек-лист ручной проверки владельцу.
- Мерж цепочки PR: следующую ветку сливать с `main` (`-X ours` только при проверке `git diff <старая голова>`
  пустым), удалять ветку — только после того, как PR смержен (удаление головы закрывает PR).

**Темы pets-ui (2026-10-21):**
- `observe_window_appearance` (и `window.appearance()`) у Windows-платформы gpui меняется только при смене
  светлая ↔ тёмная: на `ImmersiveColorSet` gpui сравнивает вид и молчит, если он прежний (смена акцента), а
  высокая контрастность приходит `WM_SETTINGCHANGE` с `SPI_SETHIGHCONTRAST`, не `ImmersiveColorSet`. Акцент и
  контрастность — своим потоком (`RegNotifyChangeKeyValue`), рецепт «Темы оформления».
- `cx.refresh_windows()` перерисовывает и закэшированные view (`window.refreshing` отключает повтор кэша) —
  то, что нужно после смены темы; `notify` каждой view не нужен.
- `cx.update_global` — метод трейта `BorrowAppContext`: без `use gpui::BorrowAppContext` его «нет у `App`».
