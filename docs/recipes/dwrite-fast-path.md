# Быстрый путь DirectWrite

**Применимость:** любое приложение на gpui, Windows, текст моноширинным шрифтом без лигатур.

**Проблема.** `layout_line` на каждую новую строку создаёт `IDWriteTextFormat` и `IDWriteTextLayout`: 40–100 мкс
на строку. Кэш строк gpui не спасает при смене всего экрана: все ряды новые, и шейпинг занимает четверть кадра.

**Решение** (`crates/pets-gpui-windows/src/direct_write/fast.rs`). Строка, где результат не зависит от соседних
символов, собирается из таблицы по (шрифт, размер), без COM:
1. Символы — только диапазоны `RANGES`: ASCII, Latin-1, кириллица, пунктуация. Всё остальное — старым путём, целой строкой.
2. Таблицу заполняет сам старый путь, по одному символу. Так ловятся запасной шрифт, `locl` по локали и всё, что
   DirectWrite делает с символом без соседей. Слот `Fast` — только один глиф своего шрифта в нуле.
3. Зависимость от соседей — разбор GSUB, GPOS и `kern` один раз на шрифт (`scan_tables`). Символ, с которого может
   начаться лигатура, контекстная замена или кернинг, идёт старым путём. Не разобрали таблицу — весь шрифт старым путём.
4. Шрифт с заданными `FontFeatures` и цветной шрифт — старым путём целиком.
5. Высота строки — по первому шрифту, как в старом пути; символа нет в первом шрифте — старым путём.

Инвариант: на любой строке быстрый путь побитно равен старому (глиф, позиция, индекс, ширина, ascent, descent).
Отличается только разбиение на `ShapedRun`: старый путь режет ещё и по скриптам, потребители gpui этого не видят.
Тесты `pets_fast_*` проверяют это на корпусе: 5 семейств, 10 размеров, прогоны разных начертаний, шрифты через `add_fonts`.

**Что проверять при обновлении gpui-kit:**
- Перенести правку: `mod fast`, поле `fast`, `layout_line` как развилку, `layout_line_slow` — бывший `layout_line`,
  `fast_font_table`, `font_table`. Новое тело `layout_line` сравнить с тем, что стало `layout_line_slow`.
- Сверить старый путь с допущениями быстрого: нечётные прогоны с размером `next_up` (рвут лигатуры на стыке);
  ascent и descent берутся до применения прогонов; `apply_font_features` кладёт три включённые функции (проверка
  `count != 3` в `fast_font_table`); `ShapedGlyph` и `LineLayout` без новых полей.
- Прогнать `cargo test --manifest-path crates/pets-gpui-windows/Cargo.toml --lib --features test-support -- pets_fast_ --nocapture`:
  расхождений 0, сводка по шрифтам — доля быстрых строк Cascadia Mono и Consolas не упала.
- Снимки экранов приложения до и после совпадают попиксельно.
- Сменились шрифты приложения — добавить семейство в `FAMILIES`. Segoe UI почти целиком идёт старым путём (кернинг): так и задумано.

**Где не поможет.** Текст со шрифтом с кернингом (Segoe UI Variable: быстро идут 147 символов из 315), строки вне диапазонов,
`FontFeatures`. Кадр, где время не в шейпинге: строка на весь файл (JSON в одну строку) — там A и B равны.

**Как мерить A/B.** Память панели мультимодальна и без правки: при первом ресайзе драйвер Intel растит пул памяти
`PAGE_WRITECOMBINE` на 12,8 МБ или нет, это зависит от времени кадра, а не от кода (см. `gpui-pitfalls.md`, «Память»).
Сравнивать только чередованием и выборкой от 20 прогонов. Первый прогон после большого файла быстрее второго: порядок
в паре менять. Снимки сравнивать с масками: часы, прогресс и каретка меняются от прогона к прогону сами.
