# Журнал приложений Pets: уровни событий

Правило одно для Postman, Урфина и всех приложений Pets (решение владельца 2026-11-12: «один подход для всех»).

## Куда идёт запись

| Уровень | Файл журнала | Системный журнал (Windows «Приложение» / macOS os_log / Linux journald; источник — имя приложения) | Код |
|---|---|---|---|
| паника | при «Отладке» | «Ошибка» / `fault` / crit (2), всегда | 1000 |
| ERROR | при «Отладке» | «Ошибка» / `error` / err (3) | 1001 |
| запуск невозможен (`fatal`) | при «Отладке» | «Ошибка» / `error` / err (3) | 1002 |
| WARN | при «Отладке» | «Предупреждение» / `default`, категория `warning` / warning (4) | 1003 |
| INFO | при «Отладке» | «Сведения» / `default`, категория `info` / info (6) | 1004 |
| DEBUG, TRACE | при «Отладке» | нет | — |

Код на macOS — категория подсистемы (`log show --predicate 'subsystem == "Postman"'`), на Linux — поле
`PETS_EVENT_ID` (`journalctl -t Postman`). У os_log нет типа «предупреждение», а тип `info` не хранится на диске —
поэтому WARN и INFO там `default` в своих категориях (PAR-03, ADR Postman 0011). Нет journald — запись не идёт, как без
источника на Windows.

Подробность задаёт настройка приложения «Уровень журнала» (Ошибки / Предупреждения / Сведения / Отладка) или
переменная окружения (`POSTMAN_LOG`, `URFIN_LOG`; формат `tracing` — `info,gpui=warn`): что пропустил фильтр, то идёт
в системный журнал (не подробнее INFO). Файл журнала пишется **только при уровне «Отладка»** (или фильтре с
`debug`/`trace` в переменной), со всеми уровнями; на остальных уровнях файла нет, журнал — только системный
(решение владельца 2026-11-13). В настройке «Уровень журнала» — пояснение: где смотреть системный журнал и что файл
пишется только при «Отладке»; строка «Папка журнала» видна только при «Отладке». Повторы ограничены: одна и та же строка — не чаще раза в 10 минут,
каждой важности — не больше 20 записей в минуту. Слой — `pets_shell::SystemLog`; приложение со своим подписчиком
ставит его рядом с файловым (`registry().with(фильтр).with(файл).with(SystemLog::new("Urfin"))`).

## Какой уровень у события

Вопрос один: что должен сделать человек, увидев запись.

- **ERROR** — то, чего человек ждал, не случилось, и программа сама это не исправит: данные не показаны, не сохранены,
  не отправлены, не скопированы. Сверка папки почты не удалась, письмо не ушло, файл не скопирован, настройки не
  записаны, сервер отказал во входе, рабочий процесс (воркер, песочница) не запустился. Каждая такая запись —
  повод разбираться.
- **WARN** — программа справилась, но хуже, чем могла: взят запасной путь, повтор после сбоя удался, неверное
  значение настройки заменено умолчанием, необязательная часть недоступна (календарь у сервера без CalDAV), ответ
  сервера медленный. Работает, но если таких записей много — что-то не так.
- **INFO** — вехи, которые нужны, чтобы понять, что было до ошибки: запуск и выход (версия), учётная запись
  подключена, первая синхронизация закончена, обновление поставлено, настройка изменена. Не чаще нескольких записей
  в минуту при обычной работе; ничего на каждое действие пользователя или каждый кадр.
- **DEBUG** — подробности для разбора: команды протокола, шаги, тайминги, размеры, решения планировщика.
- **TRACE** — байты и каждый кадр.

Пограничные случаи:

- Сбой, после которого будет повтор: первый — WARN; если повторы исчерпаны и результата нет — ERROR.
- Ошибка, которую человек уже видит (тост, окно с ошибкой), — всё равно ERROR: журнал читают позже и без экрана.
- Отказ, вызванный самим человеком (отмена, неверный пароль, введённый только что), — INFO или WARN, не ERROR.
- Ошибка одной части из многих (одна папка, одно письмо, один файл из сотни) — ERROR для этой части, с её именем.

## Что не писать

Ни на каком уровне: пароли, токены, ключи; содержимое писем и файлов (байты, тексты, темы); адреса почты в системный
журнал (его читают администраторы и сборщики событий). Имя папки, имя учётной записи в приложении, код ошибки
сервера, путь к своему каталогу данных — можно.

Запись — одна строка по-английски: `цель: что случилось: почему` и поля `имя=значение` (`tracing::error!(folder =
%name, "imap: folder sync failed: {e}")`). Текст сообщения — не интерфейс, в Fluent не переводится; правя уровень,
текст сообщения не переписывать.
