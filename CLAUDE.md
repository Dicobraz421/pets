# Pets — правила для Claude Code

Общие крейты и рецепты приложений Pets. Решения владельца — `docs/decisions/` (файл на решение, приоритетнее всего).
Базис архитектуры — скилл `pets-architecture`.

## Что сюда попадает

- Только то, что нужно хотя бы одному приложению и не завязано на предметную область. Сомневаешься,
  общее ли это, — оставь в приложении.
- Интерфейс — только gpui. egui и его обвязку не переносить (Урфин на egui до своего перехода на gpui).
- Код из приложений не копировать «как есть», если он завязан на их интерфейс или контракты: общий
  вариант пишется заново, идеи — справочно.
- Рецепт (`docs/recipes/`) — проверенный подход: проблема, решение, где применим, откуда (PR, замеры).

## Порядок работы

- Процесс — скилл `pets-dev` (`skills/pets-dev/SKILL.md`): полосы `lanes.toml`, волна = PR, класс B — `.github/CODEOWNERS`.
  Перед PR: `cargo fmt --all --check`, check/clippy своего крейта, свои новые тесты (`-E 'test(...)'`).
  Полный clippy, nextest и doc-тесты — только CI (Windows, required check `gate`), локально не дублировать.
- Изменение публичного API крейта — новый файл `docs/decisions/<YYYY-MM-DD>-<slug>.md` и проверка обоих потребителей.
- Ошибки — thiserror; логи — tracing; без `unwrap`/`expect` вне тестов.

## Границы задачи

- Делать только то, что в карточке. Замеченное сверх неё — строкой в «Решения для владельца», не в diff.
- Нет обязательного входа (карточки, контракта, файла из `read:`, решения) — стоп: вопрос владельцу, без догадок.
- «Готово» — только с доказательством в теле PR: зелёный `gate`, имя нового теста или снимок сцены.
- Правило живёт в одном месте: процесс — `skills/pets-dev`, архитектура — `pets-architecture`, решения —
  `docs/decisions/`. Здесь — только ссылки и то, что нужно на каждом старте.
- Временное — вне репо (`target/`, scratch); в git не класть архивы, выгрузки, `*_old`, `final2`.
